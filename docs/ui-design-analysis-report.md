# Priority Todo UIデザイン分析レポート

作成日: 2026-05-17

## この文書の目的

ユーザーから共有されたUI参考URLと画像をもとに、Priority Todo の次期UI改善で使うデザイン方向性を整理する。

この文書は実装仕様そのものではなく、UIを判断するときの参照資料として使う。実装前には `AI_RULES.md`、`WORKFLOW.md`、`docs/work-plan.md` とあわせて確認する。

## 結論

Priority Todo のUIは、単にガラス風・アニメーション風に寄せるのではなく、次の方向に寄せるのがよい。

> 静かで見やすい学生向け課題管理UIに、必要な場所だけ意図のある動きとガラス感を加える。

目指す印象は「派手なTodoアプリ」ではなく、「毎日開いても疲れない、でも触ると気持ちいい課題管理アプリ」。

特に重要なのは次の3点。

1. 課題作成画面を、入力順序が自然な1本道のフォームにする。
2. 今日画面では、なぜその課題が表示されているかを短く説明する。
3. モーションは装飾ではなく、保存・完了・切り替え・スワイプなど状態変化の理解を助けるために使う。

## 参考URL分析

### 60fps.design

URL: [https://60fps.design/](https://60fps.design/)

観察:

- モバイル/ウェブアプリのUIモーションを大量に集めた参考サイト。
- `Swipe`、`Tabs`、`Tap`、`Tooltip`、`Widget`、`Zoom` など、Priority Todo の主要操作に近いカテゴリがある。
- 例として、下部ナビ、カード遷移、空状態、スワイプ、タップフィードバックなどが多い。

Priority Todo への示唆:

- カレンダー月移動は一瞬で切り替えず、横方向に滑らかに移動する。
- 下部ナビは選択状態が「移動している」とわかる小さなモーションを入れる。
- 課題カードの完了、保存、展開、折りたたみには短い反応を入れる。
- モーション時間は短く、日常利用で邪魔にならない範囲にする。

使いどころ:

- カレンダーの月スワイプ。
- 下部ナビの選択インジケータ。
- 課題カードの完了/復元。
- 詳細設定の展開。
- Moodle取り込み候補の追加/除外。

### yui540/css-animations

URL: [https://github.com/yui540/css-animations](https://github.com/yui540/css-animations)

関連ページ: [https://yui540.com/animation-samples](https://yui540.com/animation-samples)

観察:

- CSSアニメーションの実験場として作られている。
- JavaScriptで複雑に制御するより、CSSだけで軽く作れる表現の参考になる。
- サンプルは「遊び」の強いものもあるため、アプリ本体にそのまま入れるより、動きの質感だけ参考にするのがよい。

Priority Todo への示唆:

- 保存、完了、追加、展開などはCSS中心の軽いアニメーションで十分。
- 常時動く装飾は避ける。
- `prefers-reduced-motion` に対応し、動きが苦手なユーザーには抑制する。

使いどころ:

- 完了時のチェック反応。
- 保存完了の小さなフィードバック。
- 詳細設定のフェード/スライド。
- 空状態の控えめな登場。

使いどころ:

- 日付選択ポップオーバー。

## 共有画像からの分析

### 画像1: UI参考サイト一覧

観察:

- Motion、Patterns、A/B Tests、Inspiration、Breakdowns、UI components と、UIを複数の観点で調べる構成になっている。
- 「見た目の参考」だけでなく、「部品」「検証」「分解」「動き」を分けて考える姿勢が重要。

Priority Todo への示唆:

- UI改善を「なんとなく綺麗にする」ではなく、次の観点で分けて進める。
  - Motion: 動きの質感。
  - Patterns: 信頼・自動化・説明責任。
  - A/B Tests: 変更仮説。
  - Inspiration: 細部の気持ちよさ。
  - Breakdowns: 実在アプリの構造分析。
  - Components: 部品の役割と標準化。

### 画像2: 太めのモノクロアイコン群

観察:

- 線と塗りのコントラストが強い。
- 細い線よりも、少し丸みと重さのあるアイコンが目立つ。
- アイコン単体で状態を表現しやすい。

Priority Todo への示唆:

- アイコンは線幅とサイズを統一する。
- 小さすぎる淡いアイコンは避け、操作可能な要素は見つけやすくする。
- 色で意味を増やしすぎず、形とラベルで意味を伝える。

注意:

- 全部を黒い太アイコンにすると学生向け課題管理アプリとして少し重い。基本は落ち着いた線アイコン、重要操作だけ太めにする。

### 画像3: pill型の滑らかな操作バー

観察:

- 左にアイコン、中央に文脈名、右にアクションチップがある。
- 背景は白/薄灰色で、角丸と影が柔らかい。
- 「Calendar」と「Sync Events」が1つの文脈内にまとまっている。

Priority Todo への示唆:

- 連携タブやカレンダー上部に合う。
- 「画面名 + 主要アクション」を1つの横長バーにまとめると、情報が散らかりにくい。
- 課題作成画面の上部バーにも応用できる。

使いどころ:

- 連携タブ: `連携` + `ICSを読み込む` / `同期`
- カレンダー: `2026年5月` + `今日`
- 課題作成: `新しい課題` + `保存`

注意:

- pill型を乱用すると全体が丸くなりすぎる。ナビ、ツールバー、チップなど役割が明確な場所に限定する。

### 画像4: 暗色のアニメーションアイコンギャラリー

観察:

- アイコン自体が主役で、操作したくなる見せ方になっている。
- 暗色背景と白アイコンのコントラストが強い。
- アニメーションアイコンは「触ったら反応する」期待を作る。

Priority Todo への示唆:

- Priority Todo 全体を暗色UIにする必要はない。
- ただし、アイコンが動くことで操作の結果を伝える考え方は使える。
- `同期中`、`完了`、`保存`、`復元` など状態変化があるアイコンに限定するとよい。

## Priority Todo のデザイン原則

### 1. 課題管理アプリとして静かに見やすい

- 背景は白から淡いグレーを基本にする。
- 色は授業色、状態色、主要アクセントに限定する。
- 赤は削除、期限超過、重大警告に限定する。
- 角丸、影、ぼかしは役割を持たせる。

### 2. ガラス風UIは限定して使う

ガラス風は次の場所に限定する。

- 下部ナビ。
- 上部の小さなツールバー。
- モーダル/シートの背景。
- カレンダーの月操作バー。

避けること:

- カードの中にカードを重ねる。
- すべてのカードを半透明にする。
- 背景や装飾のためだけにぼかしを多用する。

### 3. モーションは状態変化の説明に使う

優先して動かす対象:

- カレンダーの月スワイプ。
- 下部ナビの選択移動。
- 課題完了。
- 保存完了。
- 詳細設定の展開。
- 日付選択。
- 同期中/同期完了。

避けること:

- 常時ゆらゆら動く装飾。
- 画面全体が毎回大きく動く演出。
- 意味のない回転や拡大。
- 動作が長すぎて入力を邪魔する演出。

目安:

- タップ反応: 80-140ms。
- ボタン/チップ状態変化: 120-180ms。
- シート/詳細展開: 180-260ms。
- カレンダー月スワイプ: 260-380ms。
- 完了演出: 300-500ms以内。

### 4. 自動化は必ず説明できるようにする

Priority Todo は、時間割・繰り返し・Moodleから課題を自動生成する。便利な一方で、理由が見えないと不安になる。

必要な表示:

- なぜ今日表示されているか。
- いつから表示されるか。
- 締切はどこから取ったか。
- Moodle候補がどの授業に紐付いたか。
- 祝日スキップが効いているか。
- 同期で何が追加/変更されたか。

## 課題作成画面の方向性

課題作成画面は、Priority Todo の最重要UIとして再設計する。

推奨構成:

```text
キャンセル        新しい課題        保存

課題名

授業

締切
2026/05/15（金） 16:00

課題に取り組む期間
2026/05/13（水）16:00 から締切まで

最優先

提出先URL

メモ

詳細設定
繰り返し / 通知 / テンプレート化
```

方針:

- `課題 / 時間が決まった予定` の切り替えは廃止する。
- タスクタブのプラスボタンは課題作成に絞る。
- 予定の追加はカレンダー側の導線に寄せる。
- `課題に取り組む期間` は開始日時を選ぶUIにする。
- 終了日は基本的に締切と一致させる。
- 開始日選択ではミニカレンダーを出し、締切より後の日付は選択不可にする。
- `最優先` は締切ではなく、取り組む期間の下に分離する。
- `提出先URL` はメモより上に置く。
- 詳細設定は必ず入れ、繰り返し/通知/テンプレート系を格納する。

補助文の例:

```text
5/13 16:00 からタスクに表示されます。
締切後は期限超過として表示されます。
```

## 今日画面・課題カードの方向性

課題カードは、装飾よりも「判断の速さ」を優先する。

表示したい情報:

- 課題名。
- 授業名。
- 締切。
- 表示理由。
- 取り組み開始日。
- 繰り返し/テンプレート由来かどうか。
- Moodle由来かどうか。

状態ラベル例:

```text
今日から表示
締切まで2日
毎週火曜
Moodleから追加
祝日スキップあり
```

方向性:

- カード内の色数を減らす。
- 緊急度は色だけに頼らずラベルで伝える。
- 完了ボタンは見つけやすく、誤タップしにくい位置に置く。
- 完了後は短いトーストと `元に戻す` を出す。

## 下部ナビの方向性

タブ名の見直し:

- `タスク`
- `カレンダー`
- `時間割`
- `連携`
- `完了`

方針:

- `Moodle` タブは限定的すぎるため、`連携` に変更する。
- 連携タブには `.ics` 取り込み、将来のMoodle URL同期、外部連携を置けるようにする。
- 右下のプラスボタンは、原則タスクタブだけに表示する。
- カレンダーでは日付タップや日付長押しから追加導線を出す。
- 時間割では授業追加導線を専用に置く。

## カレンダーの方向性

現状の課題:

- 月スワイプ時の切り替えが急で、画面が一瞬で変わって見える。

改善方針:

- 横スワイプに追従して前月/今月/翌月が移動する。
- 一定距離を超えたら次月へ進む。
- 距離が足りない場合は元に戻る。
- 月変更後は滑らかに着地する。

使うべき感覚:

- 重すぎない。
- 速すぎない。
- 指の動きに反応していると感じる。

## 時間割・連携の方向性

Moodle連携ONの場合:

- 時間割番号/コースコードを必須にする。
- 未入力なら保存ボタンを無効化するか、保存時に明確なエラーを出す。
- コードがなぜ必要かを短く説明する。

Moodle連携OFFの場合:

- コードは任意。
- 非Moodleユーザーが重い初期設定を強制されないようにする。

連携タブ:

- `.ics` 取り込み。
- 将来のMoodle URL同期。
- 同期ログ。
- 秘密情報に関する注意。
- 未分類カテゴリの割り当て。

## 祝日スキップの確認方針

重要な区別:

- 祝日に課題がある: OK。
- 授業日基準の課題が、祝日で授業がない日に生成される: NG。

必要なUI:

- 繰り返し設定で `毎週この曜日` と `授業日基準` を区別する。
- `授業日基準` の場合だけ祝日/休講/長期休暇のスキップを使う。
- 次回生成プレビューで、スキップされた日がわかるようにする。

## 実装優先度案

### Phase UI-1: 課題作成画面の再設計

- 課題専用フォームにする。
- `課題に取り組む期間` を導入する。
- ミニカレンダーで締切後を選択不可にする。
- 最優先トグルを分離する。
- 詳細設定を必ず下部に置く。

### Phase UI-2: 今日画面と課題カードの信頼性改善

- 表示理由ラベルを追加する。
- 締切、開始日、繰り返し情報を整理する。
- 完了時のトースト/元に戻すを入れる。

### Phase UI-3: 下部ナビとプラスボタン整理

- `Moodle` を `連携` に変更する。
- プラスボタンをタスクタブ中心にする。
- 各タブ固有の追加導線を整理する。

### Phase UI-4: カレンダーのスワイプ改善

- 月移動を滑らかにする。
- 指の動きに追従する遷移にする。
- `prefers-reduced-motion` に対応する。

### Phase UI-5: 連携・Moodle確認画面の信頼性改善

- Moodle候補の編集性を高める。
- 自動分類理由を出す。
- 同期ログ/秘密情報の説明を整える。

## デザイン判断チェックリスト

UIを変更するときは、次を確認する。

- その動きは状態変化を説明しているか。
- その色は意味を持っているか。
- そのカード/枠/影は情報のまとまりを助けているか。
- そのラベルは学生が自然に理解できる言葉か。
- Moodle非対応ユーザーにも重すぎないか。
- 自動生成/自動分類の理由が見えるか。
- モバイル幅で文字が詰まらないか。
- `prefers-reduced-motion` に配慮しているか。
