# カレンダー・Todo UI調査メモ（2026-07）

## 目的

Priority Todo の見た目をすぐ変更するためではなく、次のUI改善フェーズで迷わないための判断材料を残す。

対象はスマートフォン利用を前提に、Googleカレンダー、Notion、Todoist、Microsoft To Do、TickTick を中心に確認した。

## 先に決めるべき方向

Priority Todo は、汎用予定表と多機能な生産性ツールの中間を狙わない。

- カレンダーは「締切の分布と授業予定を把握する」ために使う。
- 今日画面は「次に取り組む課題を決める」ために使う。
- 時間割は「授業とMoodleコードを整える」ために使う。
- 詳細設定や分類は、必要なときだけ開く。

この役割分担を崩すと、画面ごとに情報と操作が重複して、ごちゃついて見える。

## 参考アプリから得る原則

### Googleカレンダー

Googleカレンダーは、月表示とスケジュール表示を切り替え、日付タップでその日の内容へ移る構造である。月全体を眺める場と、選んだ一日の予定を読む場を混ぜない点が重要である。

- 月グリッドは日付と少数の状態だけを置く。
- 選択した日だけ、画面下のシートに予定・課題を出す。
- 下側の日付を選んでも、選択日とシートが見切れないよう月グリッドの位置を調整する。
- 月、予定リスト、日表示のように「見る粒度」を切り替える。

Priority Todo への採用候補:

- 月カレンダーは課題名を詰め込まず、最大1〜2件の短い表示と件数に抑える。
- 日付タップ時は、下から高さが決まった詳細シートを出す。
- カレンダー本体の不要な縦スクロールをなくし、選択日が常に読める位置に収める。

参照: <https://support.google.com/calendar/answer/6110849>、<https://support.google.com/calendar/answer/9901136>

### Todoist

Todoistは、リスト、ボード、日・週・月カレンダーを用途ごとに切り替え、Today / Upcoming のような時間軸ビューで課題を絞る。モバイルの週表示は3日とし、情報を小さい画面に無理に詰め込まない。

- 一つの画面で全フィルター、全カテゴリ、全メタデータを見せない。
- 日表示は「今日に集中」、月表示は「先を見通す」と役割が分かれる。
- 絞り込みは表示目的を変える機能であり、常時並べる装飾ではない。

Priority Todo への採用候補:

- タスク画面の期間フィルタとカテゴリフィルタは、常時二段で広げず、主フィルタを一つに絞る。
- カテゴリが多い場合は横スクロールまたは絞り込みシートに逃がす。
- 今日画面では、授業名・締切・「なぜ今日表示されるか」だけを優先する。

参照: <https://www.todoist.com/help/articles/customize-views-in-todoist-AoHhBxFdZ>、<https://www.todoist.com/help/articles/does-todoist-support-start-dates-qhqlgZhk>

### Microsoft To Do

Microsoft To DoのMy Dayは、日ごとに取り組む対象を明示的に絞る。締切を持つタスクはPlannedへ自動的に集め、日々の行動対象と全タスクを分離している。

- 「締切がある」ことと「今日やる」ことは別の概念として扱う。
- 毎日の画面では選択肢を減らし、完了操作を最優先にする。
- 詳細項目はタップ後の詳細画面へ寄せる。

Priority Todo への採用候補:

- 「今日の課題」は開始日から締切までの表示期間で決める現行方針を維持する。
- タスクカードの最優先情報は、課題名、締切、授業、表示理由の4つまでを基本にする。
- URL、メモ、Moodle由来の詳細はカード内で常時広げない。

参照: <https://support.microsoft.com/en-US/ToDo/my-day-and-suggestions>、<https://support.microsoft.com/en-US/ToDo/managing-tasks-in-microsoft-to-do>

### Notion Calendar / データベース表示

Notionは同じデータをカレンダー、タイムラインなどの異なる見方で表示する。モバイルでは日付をタップして日単位の内容へ入る。

- 同じ情報を複数画面で重複編集させず、表示目的だけを変える。
- カレンダーは一覧性を担い、編集や細部は別の面に寄せる。

Priority Todo への採用候補:

- タスク、カレンダー、時間割で同じ編集フォームを再利用する。
- カレンダー内の課題ブロックからは、まず詳細シートを開き、必要な場合だけ編集フォームへ進む。

参照: <https://www.notion.com/en-gb/help/calendars>、<https://www.notion.com/help/category/database-views/all>

### TickTick

TickTickはタスク、カレンダー、習慣、集中、複数のリマインドなどを一つにまとめている。強みは表示選択肢の多さだが、Priority Todoでは同じ方向へ機能を増やしすぎない。

- タスクとカレンダーを一つの時間軸で扱う点は参考になる。
- ただし、タグ、習慣、ポモドーロ、統計などを同時に持ち込むと学生向け課題管理の焦点がぼやける。

Priority Todo への採用候補:

- 色は授業カテゴリの識別に限定する。
- 通知、完了、繰り返しは課題の提出忘れ防止に必要な範囲に限定する。
- 画面上の選択肢を増やす前に、既存の「時間割 × 課題 × Moodle」の流れを磨く。

参照: <https://ticktick.com/features?language=en_US>、<https://help.ticktick.com/articles/7055782166172532736>

## 次回UI改善で解く課題

### カレンダー

1. 月グリッドの高さを固定し、画面の大部分を不必要なスクロール領域にしない。
2. 日付選択時は、選択日の課題を表示するボトムシートを画面下約3分の1に表示する。
3. 月末など下側の日付を選んだときは、月グリッドを上へ寄せ、選択日とシートを同時に見せる。
4. 課題名を月マス内に詰め込みすぎず、色、短いラベル、件数で状態を読む。
5. 月移動はスワイプ中の追従感を持たせ、切り替わりを急に見せない。

### タスク画面

1. 期間とカテゴリの絞り込みを常時二段にしない。
2. ヘッダーはブランド表示より、設定・表示切替などの操作に空間を使う。
3. カードは課題名、授業、締切、表示理由を主役にし、補助情報は折りたたむ。
4. 下部ナビはPWAのセーフエリアを考慮し、コンテンツを隠さず、余白だけが残らないよう分岐を整理する。

### 連携画面

1. URL同期とファイル取り込みは同じ候補確認画面へ合流させる。
2. 秘密URLの説明は短く明確にし、長い注意書きを増やさない。
3. 未紐付けコードは、どの授業を選べば次回から自動分類されるかを一文で示す。

## 実装しないこと

- Googleカレンダーの完全な代替となる日・週・予定表の多機能化。
- Notionのような汎用データベース化。
- TickTickの習慣、集中、統計、位置通知の同時導入。

Priority Todoの価値は、大学の授業・課題・Moodleの情報を、今日の行動へつなぐことに置く。
